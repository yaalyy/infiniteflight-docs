# 7C.1 概述

### 7C.1.1

招聘团队（Recruiters）有两项主要职责：其一是在招聘流程中管理新加入者，使其加入 IFATC；其二是负责管理所有理论和实操测试，并对测试结果作出最终裁定（即通过/不通过）。



<a id="7C.1.2"></a>
<a id="7c.1.2"></a>

<a id="7c.1.2"></a>
<a id="7c12"></a>
### 7C.1.2

Recruiters 由 IFATC Manager 基于若干标准选出，其中包括但不限于：



- ATC 理论知识与实操应用


- 时区可用性
- 在 IFATC 中的资历
- 和/或对整个 IFATC 团队的贡献



任何被考虑的 Controller **必须**{.red} 至少达到 Officer 军衔，方可符合资格（这是为了确保测试项目的所有环节都能够被执行）。

### 7C.1.3 

下表列出了在 Tower 或 Radar 实操测试前，**必须**{.red} 提前告知 Recruit 的最短通知时间（包括测试地点）：



| 测试类型 | 最短通知时间 |
| -------- | ------------ |
| Tower     | 无最低要求   |
| Radar     | 24 小时*     |

**如果 Recruiter 与 Recruit 能够协商出双方都可接受的时间，通知时间可以缩短*

### 7C.1.4

为了确保测试透明度（并且在资源允许的情况下），Recruiters **不应**{.red} 对他们亲自培训过的任何 Recruit 进行 Tower 或 Radar 实操测试。

### 7C.1.5

当新的 Recruiters 被选中后，他们将被加入 Discord 中以下频道：



| 频道           | 用途                                                         |
| -------------- | ------------------------------------------------------------ |
| #leadership-hq | 此频道将作为所有领导层角色的只读公告频道。需要时，讨论将在线程中进行 |
| #recruiters    | Recruitment Team 内用于协调的主频道 |
| #tests         | Recruiters 将在此频道发布测试的分配与沟通信息 |
| #tester [VC]   | 此频道可供测试参与者作为通用休息区使用，或在测试进行中用于协调。所有反馈 **仍应**{.red} 以书面形式通过测试主题给出 |
| #test-time     | 即将进行的测试的自动通知会出现在此频道。Tester **必须**{.red} 对该帖子“react”以确认出席。有关某次测试的进一步沟通，将在 *#tests* Discord 频道中该测试对应的特定线程里进行 |
| #trainers      | Training Team 内用于协调的主频道 |
| #training      | Trainers 将使用此频道为每次已安排的培训创建一个主题。培训目标、分配事项和反馈都将在这里给出 |
| #training-time | 当 Trainers 需要 pilots 加入培训时，他们会在此频道发帖。可参加该场次的 pilots 可以对帖子“react”以表示出席。如果可用名额已满，Pilots **不得**{.red} 对该请求“react” |
| #training [VC] | 此频道可供参与者作为通用休息区使用，或在培训进行中用于协调。所有反馈 **仍应**{.red} 以书面形式通过培训主题给出 |



> 所有测试场次的协调 **必须**{.red} 按照 Recruiter 的指示在指定线程中进行

## Recruit 用户备注与活动检查

<a id="7C.1.6"></a>

### 7C.1.6

Recruiters **必须**{.red} 在招聘过程中针对任何与表现相关的问题添加用户备注（包括联系尝试以及封禁/终止）。这可确保在需要复核或对任何决定提出申诉时，系统中显示准确的摘要。此外，Recruiters **应**{.red} 至少每月对自己的 Recruits 名单进行一次全面检查，以核实活动情况。以上两项功能都可按以下步骤完成：



步骤 1

: 前往 [Dashboard](https://dashboard.infiniteflight.com)，并使用你的 IFC 凭据登录（如有需要，登录通常会自动完成）



步骤 2

: 从屏幕左侧导航栏中，在 “IFATC” 下选择 “ATC Dashboard”



步骤 3

: Recruiters 将能够看到其 Recruits 的摘要，以及每个人当前所处的阶段



步骤 4

: 选择与想要查看的 Recruit 名称同一行的紫色箭头，这将打开其 “ATC” 资料页



步骤 5

: 然后可以使用顶部导航栏浏览该资料页的不同标签，尤其是可在需要备注时选择 “User Notes”



> Recruiters **必须**{.red} 确保对与招聘相关的备注使用 “IFATC” 标签



提示

: 或者，你也可以从屏幕左侧导航栏中选择 “Recruits” 标签，然后搜索该 Recruit 以访问其资料页

## 返回的 IFATC 成员

### 7C.1.7

返回的 IFATC 成员 **必须**{.red} 以与所有 Recruits 相同的方式申请，并完成常规的 Profile Verification，以确保其仍有资格加入。

> 若返回的 IFATC 成员在离开 IFATC 后 1 年内提交加入申请，则无需完成 Tower Written Test，因此 Recruiters 可能需要根据情况使用 “Skip to Training/Practical” 按钮

### 7C.1.8

Recruiters 获得在 Infinite Flight Expert Server 飞行时以 pilot 身份发出 Violations 的权限。虽然管理该服务器是 Supervisors 的职责，但也认可 Recruiters 具备在目睹不当行为时执行此操作的经验。



<a id="7C.1.9"></a>

<a id="7c19"></a>
### 7C.1.9

以下是可被视为适合行使该权限的情况示例：

- 没有秩序的无人值守机场
- 明显违反 Expert Server 规则
- IFATC controllers 未执行指令的环境



<a id="7C.1.10"></a>

### 7C.1.10

当违规行为明显到 Expert Server 上的 pilots 正受到其他 pilots 行为的负面影响时，**必须**{.red} 发出 Violations。



在没有 Controller 的情况下，穿越其他飞机、在其他飞机上方着陆/未复飞、在受控环境中速度过快，以及/或其他明显可辨识的干扰行为，都是发出 Violation 的一些最常见原因。

### 7C.1.11

可按以下流程发出 Violations：



步骤 1

: 在地图/小地图上点击飞机图标



步骤 2

: 会显示 pilot 的 callsign/display name，点击它以打开信息标签页



步骤 3

: 点击 report 按钮并选择最合适的原因

### 7C.1.12

pilot(s) 可在 7 天内通过 IFC 上的 @appeals 对其 Violation 提出申诉 *(见上文 [1B.3.1](../1b.-violations/1b.3-incident-resolution-procedure.md#1b.3.1))*。强烈建议 Recruiters 在该时段内保留其会话回放，以便在需要时处理相关咨询。Moderator、Appeals Team 和/或 IFATC Manager 保留对申诉结果的最终裁定权。
