# 3.3 进场航班



提示

: 如果本场航班在位置、高度和速度上不会扰乱交通流，則可批准本地飞行。管制员 **应**{.red} 尽量照顾进场交通，不论飞行时间长短；但如果提出不合理的请求，会削弱对其他航空器的服务，则可以拒绝服务

## 航线进入、排序与放行



<a id="3.3.1"></a>
<a id="331"></a>
<a id="3.3.1"></a>
<a id="331"></a>
### 3.3.1

当没有雷达管制员在场时，塔台 **必须**{.red} 至少向 **所有** 航空器发出航线进入和放行，无论航空器在塔台频率上如何通联。飞行员即使没有进近管制，也可以在飞行预定进近程序时，使用 ILS、GPS 或目视进近报告进场。所分配的航线进入方式和顺序仍将取决于交通情况，不过应尽可能满足已公布的进近程序 *(见下方 3.3.1.1)*。 



> 管制员在发放航线进入时，**应**{.red} 考虑航空器飞行计划（尤其是 STAR 或仪表进近）；不过，交通流和常识 **也应**{.red} 一并考虑（例如，如果 STAR 会让某架航空器直接进近，但由于交通原因，该航空器更适合进入风后；那么管制员 **应**{.red} 主动管理这一点）



![Image 3.3.1.1 - Tower Sequencing](../../../_images/manual/graphics/atc-tower-sequencing.jpg)



<a id="3.3.2"></a>
<a id="332"></a>
<a id="3.3.2"></a>
<a id="332"></a>
### 3.3.2

如果管制员不确定应使用哪种航线进入方式（例如，如果航空器离得还很远），可以先发送 “Continue Inbound”，但管制员 **必须**{.red} 在航空器进入航线前 **之前** 更新其航线进入方式 *(见上方 [3.3.1](3.3-inbounds.md#3.3.1))*。同样地，如果管制员不确定航空器的排序编号，可以先发送不带顺序的航线进入，但当管制员知道该将该航空器安排到何处时，**必须**{.red} 进行更新。

## 跑道变更



<a id="3.3.3"></a>
<a id="333"></a>
<a id="3.3.3"></a>
<a id="333"></a>
### 3.3.3

管制员 **应**{.red} 尝试满足航空器对不同跑道的请求，只要这不会影响对其他航空器提供的服务水平。



<a id="3.3.4"></a>
<a id="334"></a>
<a id="3.3.4"></a>
<a id="334"></a>
### 3.3.4

如果发出跑道变更，**必须**{.red} 重新给出新的航线进入和放行（是否使用排序取决于交通情况）。

## 允许机动进近



<a id="3.3.5"></a>
<a id="335"></a>
<a id="3.3.5"></a>
<a id="335"></a>
### 3.3.5    

如果航空器处于航线中，**必须**{.red} 使用 “Cleared for the Option”，因为这会让飞行员可以选择着陆 / 触地复飞 / 停止后复飞 / 低空进近。



<a id="3.3.6"></a>
<a id="336"></a>
<a id="3.3.6"></a>
<a id="336"></a>
### 3.3.6

如果航空器已经在最初起飞放行或前一次着陆放行中被指示执行左/右航线，那么就不再需要使用 “make left/right traffic”，因为默认飞行员会继续按该航线飞行，除非另有指示。如果飞行员获得了新的航线进入或新的跑道，那么在允许机动进近时，**必须**{.red} 告知飞行员是左航线还是右航线。
