## Hold Short

<a id="3.2.1"></a>
<a id="321"></a>
<a id="3.2.1"></a>
<a id="321"></a>
### 3.2.1    

如果航空器请求起飞，而你无法给予放行或发出 LUAW 指令，那么 **必须**{.red} 使用 "hold short" 指令，"standby" 等其他指令并不合适。

## 离场顺序 

<a id="3.2.2"></a>
<a id="322"></a>
<a id="3.2.2"></a>
<a id="322"></a>
### 3.2.2

如有需要，管制员可以使用 Departure Sequence 菜单向准备离场的航空器提供顺序信息（当航空器因滑行道布局等因素而不清楚谁先离场时，这尤其有用）。如果航空器是第 1 架离场，或者管制员不确定顺序编号，那么 **必须**{.red} 使用 "Hold Short"；不过在其他任何情况下，管制员都可以视情况告知航空器其离场顺序。此外，航空器不必排在队首才能报告 "ready for departure"（也可以使用 "in sequence" 信息） - 这对于规划很有帮助，尤其是在使用 Intersection Departures 时更是如此 *(见下方 [3.2.5](3.2-departures.md#3.2.5))*。



> 已获准起飞的航空器不再被视为处于离场顺序中 - 因此，下一架在等待线前的航空器被视为第 1 架离场。然而，如果某架航空器已被指示 LUAW，那么下一架在等待线前的航空器被视为第 2 架离场

## Line Up & Wait (LUAW)

<a id="3.2.3"></a>
<a id="323"></a>
<a id="3.2.3"></a>
<a id="323"></a>
### 3.2.3    

LUAW 是一项有用的工具，可在满足间隔规则后让航空器进入跑道并为即将到来的离场做好准备 *(见上方 [3.1](3.1-separation.md#3.1-separation))*。但也 **应**{.red} 考虑预期间隔，尤其是在离场/离场序列中。如果第一架航空器已经开始滑跑，请考虑第二架航空器排入跑道并开始起飞滑跑需要多长时间。如果可以判断第一架航空器将已离地，那么你就可以省去额外的指令，直接放行下一架航空器起飞；不过，**应**{.red} 考虑前机的预期爬升速度 *(见上方 [3.1.1](3.1-separation.md#3.1.1))*。只要不会影响即将离场的第一架航空器的完整间隔，管制员可以向多架航空器发出 LUAW 指令。

## Back-Taxi

<a id="3.2.4"></a>
<a id="324"></a>
<a id="3.2.4"></a>
<a id="324"></a>
### 3.2.4    

如果进入跑道全长的唯一方式是 back-taxi，那么管制员 **应**{.red} 发出 back-taxi 指令，从而让飞行员自行决定起飞所需的跑道长度。需要注意的是，back-taxi 由飞行员自行决定，因此即使已获准 LUAW 或起飞，飞行员也可能选择 back-taxi。管制员 **应**{.red} 主动从最坏情况角度规划间隔，尤其 **应**{.red} 预期航空器 back-taxi 的速度不会快于正常滑行速度。

## Intersection Departures

<a id="3.2.5"></a>
<a id="325"></a>
<a id="3.2.5"></a>
<a id="325"></a>
### 3.2.5    

Intersection departures 是优化离场顺序的一种很好的方法，因此 **必须**{.red} 使用，除非它会影响离场/到达流量。管制员 **不应**{.red} 将 intersection departures 视为“插队”，而应将其作为优势来提供更高效的服务。例如，两架进近之间看似不足以让一架民航机离场的间隔，可能对一架快速喷气式飞机来说就很合适？它为管制员提供的灵活性是一种工具，而不是阻碍。

## 起飞



<a id="3.2.6"></a>
<a id="326"></a>
<a id="3.2.6"></a>
<a id="326"></a>
### 3.2.6

喷气式航空器在到达所分配离场跑道的等待线时，默认已准备好离场。管制员可在航空器请求离场 **之前** 就发出 line up & wait 或起飞放行。



<a id="3.2.7"></a>
<a id="327"></a>
<a id="3.2.7"></a>
<a id="327"></a>
### 3.2.7    

"Immediate Take-Off" 的使用 **应**{.red} 仅保留给离场/到达间隔的情况，也就是如果离场不迅速执行，极有可能失去间隔的情形。通常这是指航空器在最后进近上且距离在 2nm 或以内，不过这也取决于相关航空器的最后进近速度，以及待离场航空器的类型，例如 777 与 737 *(见下方 [3.2.8](3.2-departures.md#3.2.8))*。



<a id="3.2.8"></a>
<a id="328"></a>
<a id="3.2.8"></a>
<a id="328"></a>
### 3.2.8    

航空器标签上以 nm 显示的距离是相对于塔台的距离，而不是航空器正在着陆的跑道入口。鼓励管制员计算航空器距跑道入口的距离，以便在间隔接近时有所准备。一个好方法是查看航空器高度；当航空器以标准 3 度下滑道飞行时，假设机场标高为 0ft，那么从接地点到 2nm 的距离对应的高度大约为 600ft *(见下方 [6.11.4](../6.-radar/6.11-instrument-landing-system-(ils)-approach.md#6.11.4))*。



<a id="3.2.9"></a>
<a id="329"></a>
<a id="3.2.9"></a>
<a id="329"></a>
### 3.2.9    

当当前 ATIS 正在播报 "Straight Out Dept." 时 *(见下方 [4.2.1](3.2-departures.md#4.2.1))*，每次发出的起飞指令都 **应**{.red} 使用 "fly runway heading until at or above XXXXft" 作为最后提醒；可用选项包括 1000ft、3000ft 和 5000ft AAL（向下取整到最接近的 500ft）。航空器爬升率可能差异很大，因此，尽管航空器已被指示在达到特定高度前保持跑道航向，但当 ATIS 选择了 "Straight Out Dept." 时，只要离场航空器尚未脱离任何冲突，航空器就不能偏离跑道航向。



<a id="3.2.10"></a>
<a id="3210"></a>
<a id="3.2.10"></a>
<a id="3210"></a>
### 3.2.10 

SID 通常会在起飞后不久转向远离机场；因此，如果正在使用 "Straight Out Dept."，管制员 **应**{.red} 注意这可能会阻止飞行员按所选 SID 飞行 *(见下方 [4.2.1](3.2-departures.md#4.2.1) 和 [6.4.3](../6.-radar/6.4-departure-check-in.md#6.4.3))*。

## 频率切换

<a id="3.2.11"></a>
<a id="3211"></a>
<a id="3.2.11"></a>
<a id="3211"></a>
### 3.2.11

离场航空器 **应**{.red} 在离场端外 1/2 英里处被指示进行频率切换，除非存在潜在冲突（这些 **必须**{.red} 在批准频率切换前解决）。管制员 **应**{.red} 避免在飞行关键阶段切换频率（例如刚抬轮之后）。



Tip

: 如果航空器没有切换频率，直接滑动该航空器的数据条即可。无需多次发送频率切换请求或警告
