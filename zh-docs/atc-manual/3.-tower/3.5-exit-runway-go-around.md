## 脱离跑道



<a id="3.5.1"></a>
<a id="351"></a>
<a id="3.5.1"></a>
<a id="351"></a>
### 3.5.1    

当航空器达到安全且受控的速度时，**应**{.red}发出 Exit Runway 指令，通常低于 70kts *(有关例外请参见下方 [3.5.2](3.5-exit-runway-go-around.md#3.5.2))*。不 **应**{.red}不必要地使用 expedite 指令。通常，如果另一架航空器已在跑道上排好队准备起飞，那么在最后进近 2nm 内的航空器，或在最后进近 3nm 内的航空器，都需要使用此指令。



提示

: 如果航空器处于进场航线中且尚未报告 full stop，管制员可以假定该航空器打算执行 touch & go 或 stop & go *(见上方 [3.3.5](3.3-inbounds.md#3.3.5))*。在这种情况下，应延迟发出 exit 指令，直到能够明确该航空器意图为 full stop（即：要么已经开始脱离跑道，要么剩余跑道长度已不足以让该航空器再次起飞）



<a id="3.5.2"></a>
<a id="352"></a>
<a id="3.5.2"></a>
<a id="352"></a>
### 3.5.2

时间关键的管制指令（例如 Go-Around 指令）**必须**{.red}始终优先处理。因此，在没有 Exit Runway 指令的情况下，航空器在达到滑行速度后，应在第一个可用滑行道驶离跑道，穿越 hold bars，并联系地面管制。如果航空器没有切换频率，管制员可在工作负荷允许时发出 "Frequency Change Approved" 或 "Contact Ground" 指令。



<a id="3.5.3"></a>
<a id="353"></a>
<a id="3.5.3"></a>
<a id="353"></a>
### 3.5.3

当塔台管制员在相距较近的多个跑道上进行管制时，建议使用 Exit Runway 和 Hold Short/Cross Runway 指令。随后，塔台管制员可以管理穿越流量（与起飞/进近流量进行冲突消解），在通道清空后交接给地面管制员，并最终降低管制员工作负荷。

## 复飞



<a id="3.5.4"></a>
<a id="354"></a>
<a id="3.5.4"></a>
<a id="354"></a>
### 3.5.4

"go-around"（G/A）可以由飞行员或管制员发起，用于取消进近和/或着陆。管制员**应**{.red}在发现需要执行复飞的冲突时尽量主动处理。在发出复飞指令时，**必须**{.red}使用 "left/right traffic/fly runway heading"，以保持对航空器的有效管制。无需加入进场航线，但仍需要排序（如适用）以及许可。如果与雷达管制员协同工作，**应**{.red}尽量告知对方该航空器为 "go-around" traffic，以便他们将其纳入计划；随后除非该航空器属于 VFR traffic，或管制员之间已有事先安排，否则可以将其移交给雷达管制员。在大多数情况下，从复飞返回雷达的航空器**应**{.red}被指示 "fly runway heading"。
