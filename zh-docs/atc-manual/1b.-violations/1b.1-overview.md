# 1B.1 概述

 

提示

: 一致性 **必须**{.red} 保持，因此管制员不能害怕发布违规处理。不过，宽容同样重要——管制员 **应当**{.red} 尝试站在飞行员的角度，判断其行为是恶意还是无心之失。

### 1B.1.1    

Expert Server 的目的是为飞行员提供一个尽可能真实的飞行环境；因此，管制员应严格执行该服务器的规则，这样认真使用的用户才能享受到该体验。

 

<a id="1B.1.2"></a>
<a id="1b.1.2"></a>
<a id="1b12"></a>
<a id="1B.1.2"></a>
<a id="1b.1.2"></a>
<a id="1b12"></a>
### 1B.1.2    

为帮助管制员履行这一职责，系统提供了“报告用户”功能，该功能会对飞行员发出一条“违规处理”（根据原因，系统会自动将其归类为 Level 2 或 Level 3）。违规处理分为三个等级：

 

| 违规处理         | 后果                                                         |
| ---------------- | ------------------------------------------------------------ |
| Level  1         | 当飞行员违反任一既定条件时会自动生成（见下方 Level 1 违规表）。如果飞行员在一次飞行中收到 3 次或更多此类违规，将会被自动移出服务器，并且必须开始新的飞行才能返回。 |
| Level  2 (Amber) | 飞行员会与服务器断开连接，但可以继续离线完成飞行。飞行员可通过开始新飞行立即返回 Expert Server* |
| Level  3 (Red)   | 飞行员会与服务器断开连接，但可以继续离线完成飞行。飞行结束后，飞行员将无法返回 Expert Server，访问将被限制 7 天。 |

 

**违规处理会记录在飞行员档案中，因此，如果飞行员持续收到违规处理（仅 Level 2 和 Level 3），其 Expert Server 访问限制时间会更长。目前，在 365 天滚动周期内，最多只能收到 5 次 Level 2 和/或 Level 3 违规处理，才能继续访问服务器*



+++ Level 1 违规表


| 规则                       | 违规条件                                                     |
| -------------------------- | ------------------------------------------------------------ |
| 地面超速                   | 在地面上地速（ground speed）超过 35kts，跑道除外 |
| 飞行超速                   | 在 10,000ft 以下 IAS（指示空速）超过 250kts / 超过最大速度警告（VMO/MMO） - 不适用于军用飞机 |
| 空域内特技飞行             | 在 5,000ft 以下且距离机场 5 海里范围内进行特技飞行 |
| 跑道怠速                   | 未经 ATC 放行，在跑道上静止停留超过 60 秒 |

+++



> Level 2 和 Level 3 违规 **不应**{.red} 用于那些已经可由 Level 1 违规处罚的行为。

### 1B.1.3

发布违规处理不需要事先警告飞行员，而且在存在对他人或程序缺乏尊重的情形时，**应当**{.red} 使用这一手段。不过，在存在让用户纠正的机会时，对于简单失误，管制员 **应当**{.red} 保持耐心（在不影响流量的前提下）——管制员可使用多种具体指令以及诸如“请遵循指令”之类的通用指令来协助处理此类情况。管制员 **必须**{.red} 依据具体情况作出最佳判断；如有不确定，应向 Supervisor 或更高级别人员寻求进一步指导。

### 1B.1.4

在违规申诉之后，飞行员的回放是提供事件处理证据的主要方式，但申诉团队也可能会要求提供管制员的回放（见下方 [1B.3](1b.3-incident-resolution-procedure.md)）。



提示

: 如果管制员错误地发出了违规处理，他们可以在 Discord 的 *#help-request* 频道向申诉团队“raise”工单以进行更正（见上方 [1A.2.4](../1a.-administration/1a.2-discord-rules.md#1a.2.4)）

### 1B.1.5

在处理可能与航空事故（或其他敏感话题）相关的呼号/用户名时，**应当**{.red} 谨慎判断。我们无法确定其意图是冒犯还是致敬。

### 1B.1.6

所有违规处理都会被跟踪和记录。若发现管制员滥用该系统，将会受到警告、停职或移出 IFATC（见上方 [1A.8](../1a.-administration/1a.8-disciplinary-and-suspension-procedure.md)）。如果管制员不确定是否有必要发出违规处理，**应当**{.red} 向 Supervisor 或更高级别人员寻求指导。

### 1B.1.7

对于某些不至于构成违规处理的情况，可以使用“please check the User Guide for assistance using ATC instructions”这一提示，但它 **应当**{.red} 仅在必要时且经过审慎判断后使用。不要用无数指令轰炸飞行员，试图替他们驾驶飞机——无论是飞行员还是管制员，都会犯错。该指令专门用于以下场景：发送的指令与随后飞行员的响应之间存在明显混淆，其唯一目的，是引导飞行员前往 IFC Forum，以便他们可以提问、查看教程，或直接联系管制员，从这次经历中学习。

### 1B.1.8

在**任何**情况下，管制员 **不得**{.red} 要求其他管制员代为发出违规处理。
