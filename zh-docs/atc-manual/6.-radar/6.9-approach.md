# 6.9  进近



提示

: 如果入场航空器处于不会扰乱交通流的位置、高度和速度，则可予以放行。管制员**应该**{.red}尽量接纳进场交通，不论飞行时间长短，但如果提出会降低其他航空器服务质量的不合理请求，则可以拒绝提供服务。

## 什么是进近？ 

<a id="6.9.1"></a>
<a id="691"></a>
<a id="6.9.1"></a>
<a id="691"></a>
### 6.9.1    

进近空域从地表到 FL180，并且在机场周围 50nm 范围内，不过如果认为机场标高具有重要影响，也可以将其纳入考虑 *(见上文 [5.2.1](../5.-airspace/5.2-on-guard-procedures.md#5.2.1))*。以下是你在开放进近席位**之前**{.red}**必须**{.red}注意的清单（也建议你自己先飞一遍进近，这样你就能确定提供良好进近服务所需的理想高度和向量）：

 

 -    机场标高：通过确定标高，可用于找出最佳截获高度 *(见下文 [6.11.5](6.11-instrument-landing-system-(ils)-approach.md#6.11.5))*。

 -    跑道出口：快速出口滑行道（RET）会让航空器比 90 度出口更快离开跑道；如果航空器必须 back-taxi 才能离开跑道，那么在安排最终进近间隔时**必须**{.red}将这一点考虑在内。

 -    如果你的覆盖范围内的塔台频率上有管制员，请与他们协调，确认离场/进场策略以及正在使用的跑道。此外，当航空器在机场之间飞行时，还应与其他雷达管制员提前安排交接点、高度和航向 *(见上文 [3.6.1](../3.-tower/3.6-tower-working-with-radar.md#3.6.1))*。

 -    机场航图：管制员**应该**{.red}获取该机场的进近航图，因为这会提高你的态势感知，尤其是地形感知 *(见下文 [6.9.6](6.9-approach.md#6.9.6))*。

## STAR 和初始向量引导

<a id="6.9.2"></a>
<a id="692"></a>
<a id="6.9.2"></a>
<a id="692"></a>
### 6.9.2    

需要注意的是，大多数 STAR 通常发生在进近空域内 *(见上文 [5.1.1](../5.-airspace/5.1-airspace.md#5.1.1))*；不过，如果存在 Center 管制员，则**所有**{.red}相关管制员之间**必须**{.red}进行协调，以确保提供无缝服务。



<a id="6.9.3"></a>
<a id="693"></a>
<a id="6.9.3"></a>
<a id="693"></a>
### 6.9.3

与进近首次联系时，航空器应当提出其进近请求。如果该航空器已经由先前的管制员获准沿 STAR 下降，那么该信息会显示在其飞行进程条上 *(见上文 [6.6.11](6.6-center.md#6.6.11))*。如果进近管制员希望航空器继续按先前放行的方式飞行，则**应该**{.red}回复“Continue as Filed, Expect the [approach type/runway] at [location]”。如果航空器先前正在接受向量引导、未获准按 STAR 下降，或者管制员希望下达向量/高度指令，则**应该**{.red}改用“Expect Vectors for the [approach type/runway] at [location]”。在没有 Center 的情况下，已经开始按 STAR 进行初始下降的航空器可以继续下降，并回复“Continue as Filed, Expect the [approach type/runway] at [location]”，而无需明确的下降放行 *(见上文 [6.6.12](6.6-center.md#6.6.12))*。



<a id="6.9.4"></a>
<a id="694"></a>
<a id="6.9.4"></a>
<a id="694"></a>
### 6.9.4

管制员**应该**{.red}在尽可能大的范围内让航空器继续按 STAR 进场，除非为了提高服务效率、排序或避让交通而需要向量引导 *(见下文 [6.9.5](6.9-approach.md#6.9.5))*。管制员可以选择首选 STAR，从不同方向提供多种获准程序 *(见上文 [4.2.2](../4.-atis/4.2-remarks-and-notams.md#4.2.2))*；未使用首选 STAR 的航空器**应该**{.red}被指示“Amend Flight Plan to Include Preferred STAR at Destination” *(见上文 [6.6.8](6.6-center.md#6.6.8))*，除非该航空器已经建立下降 *(见上文 [6.6.12](6.6-center.md#6.6.12))*。 



<a id="6.9.5"></a>
<a id="695"></a>
<a id="6.9.5"></a>
<a id="695"></a>
### 6.9.5

在任何时候，如果你下达了向量和/或高度指令，之后又希望航空器回到其飞行计划，**应该**{.red}分别发送“Continue as Filed”和/或“Altitude at your Discretion”告知飞行员。只要交通和地形允许，就**必须**{.red}为航空器提供尽可能直接的航路，因此在满足这些条件时，**不应**{.red}要求其完整飞行整个 STAR 程序。

## 进近图

<a id="6.9.6"></a>
<a id="696"></a>
<a id="6.9.6"></a>
<a id="696"></a>
### 6.9.6    

进近图通常可以通过任意搜索引擎，配合相关 ICAO 代码搜索“approach charts”在线找到；管制员**应该**{.red}熟悉如何阅读这些图表，因为这会提高管制员的态势感知。 

 

<a id="6.9.7"></a>
<a id="697"></a>
<a id="6.9.7"></a>
<a id="697"></a>
### 6.9.7    

MSA（Minimum Sector Altitude，最低扇区高度）是一个区域，在该区域内，如果航空器没有被放行至低于该扇区所显示的高度，则可以安全地进行向量引导并保证地形净空。大多数航图都会显示 MSA *(见下文 6.9.7.1)*，通常以圆形扇区的形式呈现（一般以机场本身或某个导航设施为中心）。每个扇区都包含一个可保证地形隔离的高度，但如果能够确保地形净空，管制员也可以将航空器向量引导至低于该高度。



![Image 6.9.7.1 - KSFO FAA Chart](../../../_images/manual/graphics/ksfo-chart.jpg)

<a id="6.9.8"></a>

### 6.9.8

从这张图 *(见上文 6.9.7.1)* 可以推断，来自北方的航空器在 5100ft 以下可确保不受地形影响，来自南方的航空器在 4500ft 以下可确保不受地形影响，而来自海上方向的航空器在 3500ft 以下可确保不受地形影响。在你自己先飞一遍该进近后再进行管制，你就能继续建立完整认知：哪里有地形高点、最佳截获高度是多少，等等。

## 飞行计划进近前缀 

<a id="6.9.9"></a>
<a id="699"></a>
<a id="6.9.9"></a>
<a id="699"></a>
### 6.9.9 

如果飞行员选择了已公布的进近方式，那么该信息会显示在管制员可见的飞行员飞行计划中。以下前缀用于帮助区分机场可用的不同进近方式：

| 前缀 | 含义                                           |
| ---- | ---------------------------------------------- |
| D    | VOR/DME 进近                                   |
| H    | RNAV (RNP) 进近                                |
| I    | ILS 进近                                       |
| J    | GLS 进近                                       |
| L    | 仅 LOC（Localizer）进近                        |
| N    | NDB 进近                                       |
| Q    | ILS/DME/VOR/NDB 的组合（两种或以上）           |
| R    | RNAV (GPS) 进近                                |
| S    | 仅 VOR 进近                                    |
| X    | LDA（Localizer Type Directional Aid）进近      |



在前缀之后，会显示跑道编号（例如 27 代表 27 号跑道）。随后会跟随任何相关后缀，如下表所示：

| 后缀      | 含义                                                 |
| --------- | ---------------------------------------------------- |
| L         | 左侧                                                 |
| R         | 右侧                                                 |
| Y 或 Z    | 用于区分使用相同引导的跑道                           |
| 1、2 等   | 表示同一引导用于某条跑道，但进近航迹不同（常见于 VOR/DME/NDB 进近） |



**示例：**

H35LZ - Runway 35L 的 RNAV (RNP) 进近，Zulu 程序
