# 6.4  离场 / Check In



提示

: 如果某个机场没有离场管制员，建议由中心或进近管制员在工作负荷允许的情况下处理离场流量（以及进场流量）；如果离场航线很可能与进场冲突，这一点尤其重要

## 离场与 SIDs

<a id="6.4.1"></a>
<a id="641"></a>
<a id="6.4.1"></a>
<a id="641"></a>
### 6.4.1    

离场管制通常包括管理：

 

 -    VFR 飞机，无论是否有飞行计划

 -    以及 IFR 飞机（其 **应当**{.red} 有飞行计划）

 

<a id="6.4.2"></a>
<a id="642"></a>
<a id="6.4.2"></a>
<a id="642"></a>
### 6.4.2    

如果正在使用直出离场，离场管制员和塔台管制员 **应当**{.red} 协调，以确保服务无缝衔接 *(见上文 [3.6](../3.-tower/3.6-tower-working-with-radar.md#3.6-tower-working-with-radar))*。



<a id="6.4.3"></a>
<a id="643"></a>
<a id="6.4.3"></a>
<a id="643"></a>
### 6.4.3    

标准仪表离场，称为 SID，是一种已发布的飞行程序，IFR 飞行计划的飞机会在离场后立即按此执行。SID 允许飞机沿着预先定义的航线离开空域（在某些情况下还会有高度/速度限制），帮助它们避开邻近空域、地形和进场流量。管制员 **应当**{.red} 在离场后尽可能让飞机继续沿 SID 飞行（因此在首次联系时不需要使用向量引导和/或高度指派），除非为了排序或避让流量而有必要。因此，管制员 **应当**{.red} 限制使用 “Straight Out Dept.”，以适应 SID 通常在离场后不久就会偏离机场方向的转弯 *(见上文 [3.2.9](../3.-tower/3.2-departures.md#3.2.9) 和 [4.2.1](../4.-atis/4.2-remarks-and-notams.md#4.2.1))*。

## Check In 的使用

<a id="6.4.4"></a>
<a id="644"></a>
<a id="6.4.4"></a>
<a id="644"></a>
### 6.4.4    

Check In 功能有两个主要作用：

 

 -    向飞行员首次联系到的**第一位**雷达管制员请求 IFR 雷达管制服务

 - 在被之前的雷达管制员**切换后**，告知雷达管制员他们现在在你的频率上

   

如果飞行员希望继续按其飞行计划飞行（包括 SID），则可预期其在离场后进行 “Check In”。管制员**必须**{.red} 对所有 “Check In” 请求回复 “Radar Contact”，这将建立双向通信、确认所提交的飞行计划，并放行其至初始巡航高度。从这时起不再需要进一步通信，不过如有需要，飞机仍可被雷达引导或分配高度 *(见下文 [6.5.2](https://infiniteflight.com/guide/atc-manual/6.-radar/6.5-flight-following#6.5.2))*。如果你确实发出了向量引导和/或高度指派，一旦不再存在冲突风险，你**应当**{.red} 分别通过发送 “Continue as Filed” 和/或 “Altitude at your Discretion” 告知飞行员。如果该飞机不再预期返回其飞行计划，或者根本没有提交飞行计划，则应使用 “Resume Own Navigation” 代替 “Continue as Filed”。



<a id="6.4.5"></a>
<a id="645"></a>
<a id="6.4.5"></a>
<a id="645"></a>
### 6.4.5

如果该飞机已经由另一位雷达管制员提供过先前服务并已完成移交，那么飞行员只需进行 Check In，新的管制员即可继续提供服务。



<a id="6.4.6"></a>
<a id="646"></a>
<a id="6.4.6"></a>
<a id="646"></a>
### 6.4.6    

不过，如果飞行员想要不同的服务，就需要主动请求。如果雷达管制员无法提供先前的服务，那么雷达管制员要么需要更改该飞机可预期的服务，要么询问飞行员的意图。
