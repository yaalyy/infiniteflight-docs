# 6.5  飞行跟踪



<a id="6.5.1"></a>
<a id="651"></a>
<a id="6.5.1"></a>
<a id="651"></a>
### 6.5.1    

Flight Following 是一种 VFR 服务，飞行员可以在有或没有 Flight Plan 的情况下请求，因此管制员可以预期飞行员会“目视避让”。雷达管制员可以确认此请求，如果飞行员有飞行计划，则应继续按照该计划飞行。



> 在繁忙时，Flight Following 或其他 VFR 服务可能会被拒绝，不过建议你在可行时引导流量，以便将飞机带离危险区域，例如 final 以及繁忙的进近/离场走廊



<a id="6.5.2"></a>
<a id="652"></a>
<a id="6.5.2"></a>
<a id="652"></a>
### 6.5.2    

不过，飞行员仍然可能根据交通情况接受向量和高度指令，雷达管制员**必须**{.red}做出这一判断，以确保与其空域内的其他飞机保持间隔。



> 需要注意的是，与其他飞机、地形以及 IMC 条件的最终间隔责任在飞行员，而不在 ATC



<a id="6.5.3"></a>
<a id="653"></a>
<a id="6.5.3"></a>
<a id="653"></a>
### 6.5.3    

如果你确实发出了向量和/或高度指令，一旦不再存在冲突风险，你**应该**{.red}分别通过发送“Continue as Filed”和/或“Altitude at your Discretion”告知飞行员（*例外情况见下方 [6.5.5](6.5-flight-following.md#6.5.5)*）。“Resume Own Navigation”**应该**{.red}在飞机不再预计返回其飞行计划，或者根本没有提交飞行计划时，替代“Continue as Filed”使用。 



<a id="6.5.4"></a>
<a id="654"></a>
<a id="6.5.4"></a>
<a id="654"></a>
### 6.5.4    

当飞机离开你的空域**并且**{.red}不会再影响任何其他由你管制的飞机时，**应该**{.red}发出频率切换指令。



<a id="6.5.5"></a>
<a id="655"></a>
<a id="6.5.5"></a>
<a id="655"></a>
### 6.5.5    

处于 Flight Following 下的飞机**不得**{.red}被询问其进近请求，因为这是一项 VFR 咨询服务，其唯一目的只是监控其飞行并在**有条件时**提供交通警告。然而，如果某架飞机正前往你所管制的机场，而且该机场很繁忙，你可以考虑以下一些选项来管理工作负荷（必要时与塔台管制员配合）：

- 在交接给塔台管制员之前，为进近排序发出向量
- 提前切换该飞机，让塔台管制员可以提供进场和排序指令
- 或者在交接前将飞机安排到航线的一段，由塔台管制员接手（类似于 Radar Vectors）
