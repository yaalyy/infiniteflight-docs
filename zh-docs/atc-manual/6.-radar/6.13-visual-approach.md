# 6.13 目视进近

 

<a id="6.13.1"></a>
<a id="6131"></a>
<a id="6.13.1"></a>
<a id="6131"></a>
### 6.13.1    

目视进近是指在 IFR 条件下，对跑道执行的一种进近，但在获得许可后，飞行员通过目视参考继续进近。这意味着，在管制员可以批准飞机执行目视进近之前，飞行员**必须**{.red}处于目视状态。为满足这一条件，必须存在目视气象条件（VMC）才允许目视进近 - 就 IF 目的而言，其**最低**要求为 3 法定英里（约 5000 米）能见度。



<a id="6.13.2"></a>
<a id="6132"></a>
<a id="6.13.2"></a>
<a id="6132"></a>
### 6.13.2    

虽然它与 Radar Vectors 相似，但根本区别在于，当飞机处于 Radar Vectors 下时，它们不会收到进近许可。因此，当飞机在遵循 Radar Vectors 后呼叫时，塔台会发出进场入口、程序排序（如需要），然后再发出许可。而目视进近则不需要进场入口，因为飞机已经获得进近许可，因此塔台只需发出程序排序（如需要）和许可。



<a id="6.13.3"></a>
<a id="6133"></a>
<a id="6.13.3"></a>
<a id="6133"></a>
### 6.13.3    

向飞行员下达目视进近有多种方式，但一般来说，在地形允许的情况下，飞机**应**{.red}被安排在一个可识别的位置，例如顺风航段、基线航段，甚至正切进近。然后，进近管制员必须要求飞机“报告机场在目视范围内”（注意，在要求飞行员“报告机场在目视范围内”之后，管制员仍然可以继续向飞行员发出雷达引导）。一旦飞行员回复已看到机场，进近管制员便可以批准其执行目视进近（可带或不带最后雷达引导），然后按适当方式移交给塔台/Unicom。



<a id="6.13.4"></a>
<a id="6134"></a>
<a id="6.13.4"></a>
<a id="6134"></a>
### 6.13.4    

某些机场有特定程序，但这取决于管制员和飞行员都使用正确的图表。可按照前文已概述的相同方法来执行 *(参见上面的 [6.9.6](6.9-approach.md#6.9.6))*。



<a id="6.13.5"></a>
<a id="6135"></a>
<a id="6.13.5"></a>
<a id="6135"></a>
### 6.13.5    

纽约 JFK（KJFK）机场在 RWY13L/R 上的目视进近 *(见下方图 6.13.5.1)* 就是一个特定程序的好例子。对于该程序，管制员需要将飞机引导至起始点，在此例中为 Canarsie（CRI）VOR。图表要求入航航向为 043，因此 040 或类似航向会比较合适，且该进近的最低高度初始为 2000 英尺。随后可指示飞行员报告机场在目视范围内，一旦确认后，即可批准目视进近并移交给塔台。在这种情况下，飞机实际上会在 RWY13L/R 的右基线航段上移交；不过，如果飞行员未能报告机场在目视范围内，则可能需要进一步雷达引导，以确保其继续沿规定航迹飞行，直到确认已看到机场为止。
