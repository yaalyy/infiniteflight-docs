## 什么是 Center？



<a id="6.6.1"></a>
<a id="661"></a>
<a id="6.6.1"></a>
<a id="661"></a>
### 6.6.1    

Center 空域从地表一直延伸到 FL600，并由地图上的白色边界定义。Center 的两个主要功能是：

 

 -    为其管制下的所有 IFR/VFR 航空器提供间隔和服务

 -    以及为飞行中的交通提供排序管理，以协助 Departure/Approach 管制员的工作负荷

 

需要注意的是，Center 不会取代 Departure/Approach，因此 **应当**{.red} 仅通过提供高空空中交通管理和排序来支持 Departure/Approach 频率。不过，如果没有 Departure 和/或 Approach 频率，Center 管制员也可以管理这片空域。



> 尽管 Center 空域由地图上的白色边界定义，但需要注意的是，任何 Center 频率的无线电发射范围都是从所选台站起 400 海里。管制员 **应当**{.red} 根据最能覆盖其所服务主要机场的位置选择设施频率。例如，如果作为 LAX 和 SAN 的 Center，则从 SNA 选择 Center 频率在运行上可能更有利

## 爬升



<a id="6.6.2"></a>
<a id="662"></a>
<a id="6.6.2"></a>
<a id="662"></a>
### 6.6.2 

在起飞后爬升中联系 Center 的航空器，或从 Departure 管制员交接过来的航空器，通常会使用“Check In”功能。Radar Control Service（或先前的服务，如果不同）将会继续执行 *(见上方 [6.4.4](6.4-departure-check-in.md#6.4.4))*。不过，如有需要，航空器仍然可以被引导矢量或分配高度 *(见上方 [6.5.2](6.5-flight-following.md#6.5.2))*。如果你确实发出矢量和/或高度指令，一旦不再存在冲突风险，你 **应当**{.red} 分别通过发送 “Continue as Filed” 和/或 “Altitude at your Discretion” 告知飞行员。如果航空器不再预期返回其飞行计划，或者根本没有提交飞行计划，则应使用 “Resume Own Navigation” 而不是 “Continue as Filed”。



<a id="6.6.3"></a>
<a id="663"></a>
<a id="6.6.3"></a>
<a id="663"></a>
### 6.6.3 

航空器如有需要，可以请求不同的服务，Center 管制员 **必须**{.red} 根据自身工作负荷决定能够提供何种级别的服务。如果航空器正在 VFR 飞行或没有飞行计划，则应使用 “Resume Own Navigation” 而不是 “Continue as Filed” *(见上方 [6.5.3](6.5-flight-following.md#6.5.3) 和 [6.5.5](6.5-flight-following.md#6.5.5))*。

## 巡航



<a id="6.6.4"></a>
<a id="664"></a>
<a id="6.6.4"></a>
<a id="664"></a>
### 6.6.4

在航空器飞行的这一阶段，管制员 **应当**{.red} 重点关注：

 

- 处于 active/away 状态的航空器，以提供间隔 *(见下方 [6.6.5](6.6-center.md#6.6.5))*
- 发出速度指令以管理交通流量
- 并在其空域边界将航空器交接给相邻设施 *(见上方 [5.1.1](../5.-airspace/5.1-airspace.md#5.1.1))*



<a id="6.6.5"></a>
<a id="665"></a>
<a id="6.6.5"></a>
<a id="665"></a>
### 6.6.5    

Center 管制员可以通过查看飞行进程条，判断某架航空器是 “active” 还是 “away”。因此，"away" 航空器 **应当**{.red} 先放置一边，并将冲突视为非故意。

 

> 通过 VNAV 下降的航空器，在被警告后若仍无响应 **且** 与其他航空器冲突，则可能会被判定违规 *(见上方 [1B.2.1](../1b.-violations/1b.2-violation-reasons.md#1b.2.1))*



<a id="6.6.6"></a>
<a id="666"></a>
<a id="6.6.6"></a>
<a id="666"></a>
### 6.6.6

如果满足所有条件，巡航中的航空器可以使用 “Resume Flight” 功能，这意味着航空器可能会在巡航阶段意外返回。对于返回的玩家造成的间隔丧失，管制员不承担责任，不过 **应当**{.red} 尽快重新建立适当的间隔最小值。

 

**Resume Flight 条件：**

- 高度 > 28,000 英尺 MSL
- 平飞
- LNAV 已激活
- 到目的地的预计航程时间（ETE）> 30 分钟
- 在航路轨迹上

 

<a id="6.6.7"></a>
<a id="667"></a>
<a id="6.6.7"></a>
<a id="667"></a>
### 6.6.7

在巡航阶段，速度控制对于交通流量管理至关重要，管制员 **必须**{.red} 熟悉其管制下航空器的典型 Mach 巡航速度 *(见下方 [6.15.5](6.15-aircraft-speed.md#6.15.5))*。Mach 增减 0.01 就可能显著改变航空器的到达时间（取决于下达指令的提前量）。因此，为了控制交通流量，Center 管制员 **应当**{.red} 在可能时使用速度控制（如果需要，也始终可以使用高度变化和矢量）。这将减轻管制员工作负荷，并防止航空器被带离其飞行计划数百英里。



<a id="6.6.8"></a>
<a id="668"></a>
<a id="6.6.8"></a>
<a id="668"></a>
### 6.6.8

IFR/VFR 半圆规则尚未实现，但它们值得记住，并且可以帮助管制员在巡航阶段为大量交通提供间隔。

 

**IFR** - 假设你处于 RVSM 空域

| 航向              | 高度层                                |
| ----------------- | ------------------------------------- |
| 360 - 179 度      | 奇数（例如 FL330、FL350、FL370 等）   |
| 180 - 359 度      | 偶数（例如 FL320、FL340、FL360 等）   |



**VFR** - 奇数或偶数高度层，并在所有高度层上额外加 500 英尺

| 航向              | 高度层                              |
| ----------------- | ----------------------------------- |
| 360 - 179 度      | 奇数（例如 1500、3500、5500 等）    |
| 180 - 359 度      | 偶数（例如 2500、4500、6500 等）    |

## STARs



<a id="6.6.9"></a>
<a id="669"></a>
<a id="6.6.9"></a>
<a id="669"></a>
### 6.6.9

标准终端进场航路，称为 STARs，是航空器在 IFR 飞行计划中从中间高度开始遵循的一种公布飞行程序。STARs 使航空器能够沿预先定义的航路到达（在某些情况下还带有高度/速度限制），这有助于它们避开相邻空域、地形和离场交通。管制员 **应当**{.red} 尽可能让航空器按 STAR 继续飞行直至到达，除非为了更高效的服务、排序或避让交通而需要矢量 *(见下方 [6.9.4](6.9-approach.md#6.9.4))*。 



<a id="6.6.10"></a>
<a id="6610"></a>
<a id="6.6.10"></a>
<a id="6610"></a>
### 6.6.10

管制员可以选择首选 STAR，从不同方向提供一系列获批程序 *(见上方 [4.2.2](../4.-atis/4.2-remarks-and-notams.md#4.2.2))*；管制员 **应当**{.red} 在初次联系时查看航空器飞行计划，以确认其是否包含目的机场的首选 STAR。未使用首选 STAR 的航空器 **应当**{.red} 被指示 “Amend Flight Plan to Include Preferred STAR at Destination”，以便航空器有时间重新提交计划。

## 下降 

<a id="6.6.11"></a>
<a id="6611"></a>
<a id="6.6.11"></a>
<a id="6611"></a>
### 6.6.11

已提交 STAR 的航空器在首次联系 Center 时，预计会执行 “Check In”；如果飞行员的飞行计划中没有 STAR，则他们 **应当**{.red} 主动联系，并请求其目的机场所需的服务或进近。如果航空器提出其他请求，例如进近请求，而当前使用的进近已知，则管制员 **应当**{.red} 回复 “Continue as Filed, Expect the [approach type/runway] at [location]”。后续的 Approach 管制员仍可在需要时更改预期进近。 



<a id="6.6.12"></a>
<a id="6612"></a>
<a id="6.6.12"></a>
<a id="6612"></a>
### 6.6.12

飞行员 **应当**{.red} 在 Top of Descent（TOD）之前不久，请求沿 STAR 下降；Center 可以回复 “Descent via the STAR Approved” 或 “Unable, Expect Vectors”。已获准沿 STAR 下降的航空器，其获批 STAR 将显示在飞行进程条上，供所有后续管制员查看，这样飞行员无需向不同管制员重复请求。如果被告知预期矢量，则 Center **必须**{.red} 提供矢量和高度指令，并在完成后发出 “Continue as Filed” 和 “Altitude at your Discretion”。如果飞行员尚未请求下降，Center 也可以指示航空器 “Descend via the STAR”（当点击航空器图标时，STAR 中内置或飞行员修改后的高度将显示在管制员界面上）。 



<a id="6.6.13"></a>
<a id="6613"></a>
<a id="6.6.13"></a>
<a id="6613"></a>
### 6.6.13

在联系 Center 之前就已经开始下降的航空器 **应当**{.red} 被授权 “Descend via the STAR”。已经建立在下降中的航空器 **不应**{.red} 被指示 “Amend Flight Plan to Include Preferred STAR at Destination”，因为这可能增加飞行员工作负荷。相反，管制员 **应当**{.red} 发出矢量以进行排序。 



<a id="6.6.14"></a>
<a id="6614"></a>
<a id="6.6.14"></a>
<a id="6614"></a>
### 6.6.14

只要所有冲突都已解决，向下一个管制设施的移交 **应当**{.red} 在横向和/或垂直边界处或之前进行。此外，Center **必须**{.red} 确保所有航空器都以有序方式前往其目的地，按照各自程序飞行，并在移交给 Approach 之前完成排序。
