# 6.14 交接至塔台/Unicom

 

<a id="6.14.1"></a>
<a id="6141"></a>
<a id="6.14.1"></a>
<a id="6141"></a>
### 6.14.1    

在管制员将飞机交接给塔台/Unicom 之前，**必须**{.red} 确保该飞机已成功建立在“预定进近航迹”上，**并且**与前方飞机保持可接受的接近率。

 

<a id="6.14.2"></a>
<a id="6142"></a>
<a id="6.14.2"></a>
<a id="6142"></a>
### 6.14.2    

适用于 GPS Approach、Radar Vectors 和 Visual Approach 的“预定进近航迹”已在上文说明 *(分别参见上文 [6.10.3](6.10-global-positioning-system-(gps)-approach.md#6.10.3)、[6.12.1](6.12-radar-vectors.md#6.12.1) 和 [6.13.3](6.13-visual-approach.md#6.13.3))*。对于 ILS 进近，管制员**必须**{.red} 确保飞机已成功截获 LOC，这一点在使用平行运行时尤为重要 *(见下文 6.14.2.1)*。不要把飞机已建立在 LOC 上与“处于锥形区内”混淆——无论飞机位于锥形区内还是外，都必须与待进近跑道的中心线对齐，才算已建立。



![Image 6.14.2.1 - Radar intercept right vs wrong](../../../_images/manual/graphics/atc-intercept-right-vs-wrong.jpg)




<a id="6.14.3"></a>
<a id="6143"></a>
<a id="6.14.3"></a>
<a id="6143"></a>
### 6.14.3    

雷达管制员**必须**{.red} 确保飞机的接近率“可接受”，并在无法维持所需间隔时发出速度控制指令（例如，如果 A 机在最后进近时地速为 180kts，而 B 机以 250kts 地速进行截获，且间隔只有 3nm，间隔可能会被破坏并导致复飞）。在间隔得到确保之前，飞机**应**{.red} 保持在当前频率上，这可能意味着要把频率转换推迟到非常晚的时候！



<a id="6.14.4"></a>
<a id="6144"></a>
<a id="6.14.4"></a>
<a id="6144"></a>
### 6.14.4

为帮助在最后进近时保持间隔，当交通量较大时，雷达管制员**应**{.red} 使用“保持 XXXkts 直到 X 英里最后进近”这类指令。飞机应将其 IAS 降至指定速度，并保持该速度直到达到指定距离，然后再进一步减速至其最终进近速度。
