### 1A.3.1

- 所有控制员在 Expert Server 上打开/关闭任何频率时，**必须**{.red} 在 *#controllers* 中宣布（包括哪些设施，例如 Ground 和 Tower）。在关闭时，**必须**{.red} 提前至少 5 分钟发出通知，并提供最后使用的 ATIS 字母。可以使用缩写代替完整设施名称 *(见上文 [1A.1.2](1a.1-discord-communication.md#1a.1.2))*
- 期望控制员通过尽可能共享、开放能够促进机场之间流量的频率，以及在 *#controllers* 中宣布之前先开放频率，来向其他控制员表示基本礼貌

- 在 *#controllers* 中，频率开放遵循先到先得原则。因此，控制员**不得**{.red} 私下保留频率，或在预期某个频率即将可用时不开放。控制员可以为社区活动承诺特定频率/位置，并且**应当**{.red} 在活动开始时由其他控制员给予其占位的机会

- 控制员**应当**{.red} 避免为没有飞机停机位出生点的机场值守或提供服务
- 使用 *@Tower Relief* 和 *@Radar Relief* 反应角色的控制员**必须**{.red} 仅使用一次，并且**必须**{.red} 包含他们关闭的机场和时间
- 使用 *@split* 反应角色的控制员**必须**{.red} 仅使用一次，并且**必须**{.red} 包含机场。建议在开放之前使用此功能
- 控制员**不得**{.red} 在其他当前已开放且处于活动频率上的控制员处标记他们，除非在操作上至关重要（这不包括在不同频率上彼此发送操作信息的控制员）
- 控制员**不得**{.red} 在 Training Server 上管制 *(例外情况见下文 [7.4.4](../7.-recruitment-and-training/7.4-radar-written-and-practical-tests.md#7.4.4))* 
- 控制员**不得**{.red} 在使用不同设备进行积极管制的同时飞行。Autopilot+ 可用于在后台进行活动飞行，同时管制或参与培训课程
- 控制员**不得**{.red} 在其他平台上（例如 BlueStacks）管制 Infinite Flight，因为控制员回放不会被保存 *(见上文 [1B.3.1](../1b.-violations/1b.3-incident-resolution-procedure.md#1b.3.1))* 
- 管制标准会被严格监控 - **期望控制员在自身能力范围内进行管制，优先保证质量而非数量**{.red} *(见下文 [1A.6](1a.6-rank-structure.md#1a.6-rank-structure))*

### 1A.3.2

所有控制员在被加入 IFATC 后，都有权签发 2 级或 3 级违规。相关指南包含在本手册中 *(见下文 [1B.1](../1b.-violations/1b.1-overview.md#1b.1-overview))*
