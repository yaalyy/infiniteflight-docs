# 2.3 跑道穿越

 

<a id="2.3.1"></a>
<a id="231"></a>
<a id="2.3.1"></a>
<a id="231"></a>
### 2.3.1    

对于跑道穿越，跑道**必须**{.red}按照其当前使用方向来指称，无论航空器位置如何，或飞行员提出什么请求都一样 *(例外情况请参见下方 [2.3.4](2.3-runway-crossing.md#2.3.4))*。例如，如果飞行员位于 RWY36 的等待位置附近，但另一端正在用于起飞和进近，则**必须**{.red}指示飞行员穿越 RWY18，而不是 RWY36。



<a id="2.3.2"></a>
<a id="232"></a>
<a id="2.3.2"></a>
<a id="232"></a>
### 2.3.2    

只有在存在合适的间隔、能够让交通安全地穿越并清空跑道边缘（不是等待线）时，才**必须**{.red}发布穿越许可。除非满足以下条件，否则**不得**{.red}允许航空器穿越：



- 出发航空器尚未开始起飞滑跑
- 出发航空器已经开始起飞滑跑，但已离地并且明显正在转弯，或已越过穿越点（无论高度如何）
- 到达航空器尚未越过跑道入口
- 到达航空器已经越过跑道入口，但要么已明显在穿越点之前离开跑道，要么已经越过穿越点



> 在所有情况下，与塔台管制员协调都是必不可少的！



<a id="2.3.3"></a>
<a id="233"></a>
<a id="2.3.3"></a>
<a id="233"></a>
### 2.3.3    

建议预判跑道穿越，并且**应当**{.red}优先使用，而不是等待飞行员请求。如果你认为需要跑道穿越，并且交通情况允许，应提前发布。



<a id="2.3.4"></a>
<a id="234"></a>
<a id="2.3.4"></a>
<a id="234"></a>
### 2.3.4

如果滑行道之间并未直接对齐，则**必须**{.red}使用 back-taxi 指令，而不是跑道穿越指令，因为飞行员将不得不在跑道上滑行后再离开。在这种情况下，跑道必须按照管制员希望航空器 back-taxi 的方向来指称（不过也可以在此基础上使用逐步滑行指令，以确保航空器从合适的滑行道离开）。
