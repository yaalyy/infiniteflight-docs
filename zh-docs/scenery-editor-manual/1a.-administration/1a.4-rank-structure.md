# 1A.4 职级结构

### 1A.4.1    

下表概述了当前采用的职级结构。晋升基于活跃度、表现和反馈：

 

| 职级          | 是否需要机场分配 | 查看 WIP 机场 | 进行同行/官方审核 |
| ------------- | ---------------- | ------------- | ------------------ |
| 学徒          | 是*              | 否**          | 否                 |
| 高级编辑      | 否               | 是            | 仅同行审核         |
| 审核员        | 否               | 是            | 是***              |

**学徒 **不得**{.red} 同时被分配超过一个机场，除非该机场已提交官方审核 *(见下文 [12.1.4](../12.-review-and-release/12.1-review-and-release-process.md#12.1.4))*。学徒可以在等待其机场审核反馈期间，被分配并开始编辑下一个机场，但在收到反馈后，**必须**{.red} 优先完成当前机场。*



***学徒只能查看分配给自己的机场，任何 WIP 机场在发布或学徒晋升为高级编辑之前都不可见*



****在进行官方审核时，审核员不会对机场进行任何编辑，除非该修改非常小且无需向编辑者反馈。任何较大的更改都会发送给编辑者，由其完成所需修改。*



> 所有编辑者都可能根据活跃度、表现和反馈在任何时候被晋升/降级！

### 1A.4.2

晋升为编辑职级会按个案处理，而不单纯依据任职时间。因此，学徒**必须**{.red} 避免询问自己何时会被晋升；而应**应当**{.red} 专注于以高标准编辑机场。编辑在晋升后会收到通知。

## 晋升为审核员

<a id="1A.4.3"></a>
<a id="1a.4.3"></a>

### 1A.4.3

审核员职级仅在有需要时授予，并授予那些在机场编辑团队中展现出高标准机场编辑能力和专业行为的编辑。



审核员团队的目的是：

- 协助场景编辑团队的日常运营
- 为个别编辑提供领导和/或指导
- 将机场分配给学徒职级的编辑
- 通过“官方审核”流程*检查编辑质量
- 以及管理场景编辑团队 Discord 频道



**审核员 **不应**{.red} 在官方审核流程中未经编辑者明确同意，就代表编辑上传更改；这样做是为了促进编辑者技能提升，并尊重其工作成果。除非官方审核中发现的问题很小、并非持续存在，且若将其留给该机场的编辑修复，则开启新一轮 OR 流程并不合理。小问题的例子包括未正确贴合的线条、建筑和/或人行道，以及具有一个或多个不准确属性的线条。建议审核员根据所发现问题的一致性和严重程度，结合待审核机场的规模与复杂度，酌情判断。例如，在 KLAX 出现 3 条未正确贴合的线条问题不算太大，但在一个小型通航机场就会是大问题。如果审核员确实决定在官方审核流程中代表编辑上传更改，则**应当**{.red} 提供所做更改的摘要，最好包含截图，以表示对编辑者工作的尊重。*

### 1A.4.4

晋升为审核员职级需要满足以下前提条件：



- 具备编辑职级，并在机场编辑的**所有**方面都表现出熟练能力
- 熟练的编辑，能以身作则并遵守所有服务器规则
- 良好的编辑记录
- 能够以尊重且专业的方式沟通

### 1A.4.5

除上述职级结构外，个人还可能在机场编辑团队中担任其他角色。如下所示：



| 职称       | 职责                                                         | 职级 |
| ---------- | ------------------------------------------------------------ | ---- |
| 版主       | 管理机场编辑团队，包括日常运营、质量保证、人事问题、绩效以及纪律性降级和/或停权 | 不适用  |



> IFC 版主存在于机场编辑团队中；不过，机场版主通常会处理大多数日常事务
