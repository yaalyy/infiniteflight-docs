# 1A.5  机场分配



<a id="1A.5.1"></a>
<a id="1a.5.1"></a>
<a id="1a51"></a>
<a id="1A.5.1"></a>
<a id="1a.5.1"></a>
<a id="1a51"></a>
### 1A.5.1    

所有处于 Apprentice 等级的编辑者（加入时的初始等级）**必须**{.red} 为其分配所有机场后才能上传。这是为了确保新编辑者不会为自己分配过大/过于复杂的机场，并且能够一次专注于一个机场，处理在同行评审和正式评审中发现的任何问题 *(见下方 [12.1](../12.-review-and-release/12.1-review-and-release-process.md))*。



> Apprentices **不得**{.red} 同时被分配超过一个机场，除非该机场已经提交进行正式评审。Apprentices 可以在等待其评审中的机场反馈期间，被分配并开始编辑下一个机场，但在收到反馈后，**必须**{.red} 优先完成当前机场。

### 1A.5.2

在已分配机场通过正式评审后，Apprentices 将晋升为 Editor 等级，并且不再需要申请机场分配 *(见上方 [1A.4.2](1a.4-rank-structure.md#1a.4.2))*。



> 在某些情况下，Editor 也可能需要 Reviewer 的手动介入。例如，从某个机场解除分配、与其他 Editor 同时协作编辑某个机场，或者该机场此前已分配给另一位 Editor。在这些情况下，是否批准仍由 Reviewing Team 自行决定，即使该 Editor 已经从 Apprentice 晋升也可能不会获批。

### 1A.5.3

对于任何与机场分配相关的请求，**必须**{.red} 遵循以下步骤：



步骤 1

: 打开官方 Infinite Flight Discord，并使用屏幕左侧的导航栏找到 “Scenery Editing” 选项卡。



步骤 2

: 点击 *#airport-assignments* Discord 频道。



步骤 3

: 在该频道中创建一个请求，说明你想编辑的机场。申请机场时必须使用以下格式：“Requesting ICAO”，以及任何其他相关信息，例如“collab with [editors name]”。



步骤 4

: Reviewer 将查看该请求，并批准机场分配或提出替代方案（尤其对于 Apprentices，如果该机场被认为过大/过于复杂，可能会出现这种情况）。



> 这会以线程的形式出现在请求下方。此后与该机场相关的所有评论**都应**{.red} 发布在该线程中，以确保机场分配不会在 Discord 频道中被淹没。

### 1A.5.4

当 Apprentices 选择希望被分配的机场时，**应**{.red} 考虑以下标准：



- 机场规模和复杂度
- 可用时间
- 能力
- Reviewer 给出的过往反馈（如适用）
