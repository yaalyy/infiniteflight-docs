# 12.1 审核与发布流程



> 当上传最近编辑过的机场的新版本时（即点击“Upload as Draft”或“Upload for Review”），编辑者需要提交一份“changelog”，用于突出说明该版本中有哪些变更。Changelog **必须**{.red} 具体明确，以确保清楚地说明哪些内容已被更改（例如：“Adjusted C19 jetbridge. Changed taxiway line type on Taxiway A”）。如有需要，可在 IFC 机场线程中补充更多细节。



<a id="12.1.1"></a>
<a id="1211"></a>
<a id="12.1.1"></a>
<a id="1211"></a>
### 12.1.1

要让你的机场在 Infinite Flight 中发布，你 **必须**{.red} 将机场提交审核，以便检查其是否符合本手册中定义的所有规则。为减轻审核员的工作量，提供了一个两阶段审核流程，如下所示：



| 审核类型 | 说明                                                                 | 可审核者           |
| -------- | -------------------------------------------------------------------- | ------------------ |
| Peer     | 审核流程中的自愿步骤，**应当**{.red} 执行，以便获得其他编辑者的反馈 | Editor 或以上      |
| Official | 强制性审核，机场 **必须**{.red} 在进入发布周期之前先提交此审核        | Reviewer 或以上    |



<a id="12.1.2"></a>
<a id="1212"></a>
<a id="12.1.2"></a>
<a id="1212"></a>
### 12.1.2

在提交审核之前，**必须**{.red} 先完成 Scenery Check，以确保机场符合所设定的限制（即性能限制、边界外对象、命名问题/重复的登机口等）：



步骤 1

: 点击 "File > Scenery Stats > Scenery Check > Check Scenery"



步骤 2

: 然后可以通过点击某个错误，再点击 "Select Items"，来找到列出的任何错误



步骤 3

: 接着你就可以在机场中看到被选中的项目，并决定是否需要更改它

## Peer Review 

<a id="12.1.3"></a>
<a id="1213"></a>
<a id="12.1.3"></a>
<a id="1213"></a>
### 12.1.3

提示

: 要将机场以上传草稿或用于审核的方式上传，必须自上次上传版本以来有过更改（哪怕只是移动一个锥桶这样的小改动）



步骤 1

: 机场完成后，**必须**{.red} 使用 "File > File Manager > Upload as Draft" 上传 *(见上方 [2.1.2](../2.-user-interface/2.1-editor-screen.md#2.1.2))*。之后，可以通过在 *#request-peer-review* Discord 频道中发布 IFC 机场线程的链接，来提交“peer”审核



> 进行 Peer Review 的编辑者 **不得**{.red} 同时接受超过 2 个机场，且 **必须**{.red} 确保自己有足够时间及时完成审核（即 **不得**{.red} 提及审核会在何时完成，因为编辑者应只在自己有空时才进行 Peer Review）。如有疑问，编辑者 **应当**{.red} 将机场继续保持为可供审核的状态 *(见上方 [1A.3.1](../1a.-administration/1a.3-editor-rules.md#1a.3.1))*



步骤 2

: 收到反馈后，编辑者就可以根据这些更改继续工作，然后要么再次提交 peer review，要么提交 official review。所有与审核相关的反馈（peer 和 official 都包括）**必须**{.red} 在 IFC 机场线程中进行，以确保保留记录



> 每个机场可获得的 Peer Review 次数没有限制，但编辑者 **应当**{.red} 只在他们认为机场已完成时才提交审核。如果在机场尚未完成前需要帮助或指导，编辑者 **应当**{.red} 使用 *#help* Discord 频道，针对他们的机场提出具体问题

### 12.1.4

提示

: 要将机场以上传草稿或用于审核的方式上传，必须自上次上传版本以来有过更改（哪怕只是移动一个锥桶这样的小改动）



步骤 1

: 当编辑者准备提交“official”审核时，可通过使用 "File > File Manager > Upload for Review" 来完成 *(见上方 [2.1.2](../2.-user-interface/2.1-editor-screen.md#2.1.2))*



步骤 2

: 反馈将由 Reviewer 在 IFC 机场线程中给出。如果需要额外更改，这些更改 **必须**{.red} 按照上述相同流程重新提交。审核员提供的反馈是强制性的。如果要求进行某项更改，则 **必须**{.red} 实施该更改，机场才会被视为已准备好发布。



步骤 3

: 当 Reviewer 认为机场已准备就绪后，机场将被标记为“Ready for Release”，并会在某个时间点纳入发布周期



> 一旦你的机场被标记为 “Ready for Release”，也不一定会在下一个周期发布。这是因为还有其他因素会决定某项内容是否会被纳入发布，更多信息可[在此](https://community.infiniteflight.com/t/airport-releases/653276)查看

## Navigation Database Update

### 12.1.5

在机场获得批准并标记为可发布后，某些更改可能要等到下一次 navigation database update 完成后，才会在应用内显示。这通常与一次发布同时进行。这适用于：



- airport boundary
- airport elevation
- airport mini-map
- runway information (such as approach types)
- start locations
- tower view point



> 例如，当机场边界发生更改时，只有在 navigation database update 之后，这个新区域内的海拔才会与机场其他部分的海拔一致。这可能意味着在这个新区域中会出现悬空或沉入地下的建筑/物体
