## 何时在起飞时联系 ATC



| 设施   | 何时                                                         |
| ------ | ------------------------------------------------------------ |
| Ground | 当你准备好进行 [pushback](atis-pushback-and-taxi.md#pushback-communication-summary) 或 [taxi](atis-pushback-and-taxi.md#taxi-communication-summary) 时，可以联系 Ground 提出请求 |
| Tower  | 当你从 Ground 被移交，或者准备起飞时（在被告知“taxi to RWY XX, contact Tower when ready”之后），应联系 Tower。与 Tower 建立联系后，你可以提出 [请求](take-off-and-departure.md#take-off-communication-summary) |
| Radar  | 当你在起飞后被 Tower 移交，或者从无管制机场起飞并进入管制员空域时，应联系 Radar（Departure/Center/Approach）。与 Radar 建立联系后，你可以通过发送 ["Check In [IFR]" 或 "Flight Following [VFR]"](take-off-and-departure.md#departure-communication-summary) 开始通信 |

## 何时在进近时联系 ATC



| 设施   | 何时                                                         |
| ------ | ------------------------------------------------------------ |
| Radar  | 抵达时，当你从另一位 Radar 管制员处被移交，或进入 [管制员空域](en-route.md#en-route-communication-summary) 时，应联系 Radar 管制员。与 Radar 建立联系后，你可以通过发送 "Check In [IFR]"、"Flight Following [VFR]" 或 [特定进近请求](descent-and-approach.md#descent-communication-summary) 开始通信 |
| Tower  | 当你从 Radar 管制员处被移交，或在没有雷达服务的情况下进场时（距离 25nm 以内且低于 10,000 AAL），应联系 Tower。与 Tower 建立联系后，你可以通过呼叫 "inbound on the [ILS/GPS/Visual], RWY XX" 来 [开始通信](landing-and-taxi-to-parking.md#landing-communication-summary)；如果未提供进近服务，则呼叫 "inbound for [landing/touch & go]" |
| Ground | 当你被 Tower 移交时（这可能以离场指令的形式出现），或者在没有离场指令/移交的情况下驶离跑道时，应联系 Ground。与 Ground 建立联系后，你可以提出 [请求](landing-and-taxi-to-parking.md#taxi-to-parking-communication-summary) |

## 与 ATC 通信时的常见错误



+++ 在没有进近许可的情况下呼叫 "inbound on the [ILS/GPS/Visual]"

如果你没有从 Radar 管制员那里收到进近许可，你必须确保通告的是 "inbound for [landing/touch & go]"，而不是 "inbound on the [ILS/GPS/Visual]"。

+++



+++ 在首次联系 Approach 时发送 "Check In [IFR]"

当与正在执行 Approach 的 Radar 管制员联系时，只需提出进近请求即可，不需要其他请求。

+++



+++ 在与 Approach 联系时发送 "requesting descent via [STAR] arrival"

当与正在执行 Approach 的 Radar 管制员联系时，只需提出进近请求即可，不需要其他请求。

+++



+++ 在发送 "Check In [IFR]" 后再请求 "Flight Following [VFR]"

联系 Radar 管制员时只发送一个请求即可 - "Check In [IFR]" 后再发送 "Flight Following [VFR]" 相当于请求两种不同的服务，这是不需要的

+++



+++ 在离场时通告 "remaining in the pattern"

如果你并不打算在机场做航线飞行，就不要通告 "remaining in the pattern"。相反，应通告你离开 Tower 管制空域的方向。

+++

## 特殊情况



| 场景                         | 描述                                                  |
| ---------------------------- | ------------------------------------------------------------ |
| Center 作为 Approach        | 当进入其空域时，你应向 Center 发出初始 "Check In [IFR]" 请求，并在接近 TOD 时发送 "requesting descent via [STAR] arrival"。当达到 FL180 时，你就可以针对目的地机场提出具体进近请求；Center 将确认该请求（视工作负荷而定）并发布向量（如需要）以及许可 |
| 没有 Ground 时的 Tower      | 如果没有激活 Ground 频率，只要条件允许，你可以自行决定 pushback 并滑行至跑道。直到你准备起飞前，不需要与 Tower 通信 |
| 管制员更替进行中             | 当管制员更替进行中时，会有一小段时间没有管制员在位。你应继续正常飞行，并将先前发出的任何许可视为有效。当新的管制员接入时，不需要任何请求，因为该管制员可以在消息日志中看到所有先前的通信 |
